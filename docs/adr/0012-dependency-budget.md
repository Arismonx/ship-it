# ADR-0012: Dependency budget

**Status:** accepted (2026-10-22); Charm exception detailed on 2026-10-25, with the review screen of `ship`.

## Rule
- Allowed by default: the Go standard library and `golang.org/x/*` (maintained by the Go team).
- Any other dependency needs an ADR stating: the need, the estimated in-house alternative, a licence compatible with ship-it's licence (Apache-2.0), the project's activity, and the transitive size.

## Exceptions granted

### Charm v2 (Bubble Tea, Lip Gloss), in `internal/surface/cli` only
**Need:** the editable review screen of `ship` (title, branch, why, tested, file selection, live checks), and later the hunk view of the split and visual stacks (user's choice). Writing a terminal UI that handles raw mode, the Windows console, the kitty keyboard protocol, colour profiles and redraws is far beyond a "small in-house alternative".

Facts verified on 2026-10-25 (module cache, `go mod graph`, `go list -deps`):

- **Licence**: MIT for both, and for every module they bring (table below). MIT code may be distributed inside an Apache-2.0 work; its notice must ship with the binary: `THIRD_PARTY_NOTICES.txt`, generated by `go run ./tools/gen` (its test fails when it is stale), is in every release archive and in the image under `/usr/share/licenses/ship/` (decision of 2026-10-25, [workflows](../design/workflows.md)).
- **Windows**: supported natively. Bubble Tea reads the console through `github.com/charmbracelet/x/windows` (Win32 console API bindings) in `charmbracelet/ultraviolet`, whose decoder reads key events with their modifier state (`decoder.go`: `VK_RETURN` plus `translateControlKeyState`), so Ctrl+Enter is told apart from Enter there.
- **Keyboard**: Bubble Tea v2 asks every terminal for basic key disambiguation (kitty keyboard protocol, flag 1, see `tea.go`, `KeyboardEnhancements`). Where the terminal answers (kitty, WezTerm, foot, Ghostty, recent iTerm2…), Ctrl+Enter arrives as `ctrl+enter`. Legacy terminals send Ctrl+Enter as CR (identical to Enter) or LF (read as `ctrl+j`): the review screen accepts `ctrl+j` and **F2** as well, and Enter ships whenever the focus is not in a text field.
- **Colours**: `charmbracelet/colorprofile` detects the terminal profile and honours `NO_COLOR`, `CLICOLOR`, `CLICOLOR_FORCE` and `TERM=dumb` (`env.go`); Bubble Tea downsamples every style to that profile.
- **Not used: `charm.land/bubbles/v2`** (v2.2.1). Its `textinput` imports `github.com/atotto/clipboard`, which runs `xclip`/`xsel`/`wl-paste` for Ctrl+V. The review screen has its own one-line editor (`internal/surface/cli/lineinput.go`, ~150 lines); pasting goes through the terminal's bracketed paste.
- **Not used: `github.com/charmbracelet/x/exp/teatest/v2`**: only a pseudo-version published on 2026-10-25 (`v2.0.0-20261025003702-835ad0048169`), experimental and too fresh. The model's `Update` and `View` are tested directly, with golden screens.
- **v1 and v2 do not mix**: v2 lives under `charm.land/...`; nothing imports `github.com/charmbracelet/bubbletea` (v1).
- **govulncheck**: no vulnerabilities found (2026-10-25).

## Guardrails
- **Only `internal/surface/cli` imports Charm** (`charm.land/...` and `github.com/charmbracelet/...`). `internal/archtest` enforces it twice: `TestImportRules` rejects a direct import anywhere else, and `TestCharmStaysInTheCLI` rejects any package whose **transitive** dependencies reach Charm, except the CLI surface and `cmd/ship`, which starts it. The core, the app, the adapters and the `mcp` surface therefore stay without a TUI.
- **Fallback without a full screen, tested**: `--plain`, `SHIP_ACCESSIBLE=1` or `TERM=dumb` give line-by-line prompts on stderr (screen readers); without a terminal on stdin, `ship` exits with code 2 unless `--yes`; with stderr redirected, one plain question. See [the review screen](../reference/cli.md#the-review-screen).
